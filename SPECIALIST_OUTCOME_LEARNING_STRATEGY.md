# SeeMind v0.66.8 — Specialist Outcome Learning & Anti-Lock-in

SeeMind must learn which external specialist actually solves which kind of residual problem. A successful HTTP/API response is not proof that the task was solved.

Strong positive evidence: authoritative/independent verification of the specialist result.
Negative evidence: later user correction, contradiction by authoritative evidence, an unresolved residual, or technical failure.

The learned unit is **provider × capability × task kind**, not provider brand prestige. This prevents a globally popular provider from dominating tasks where another specialist performs better, and allows future providers to enter without core rewrites.

Outcome learning influences selection; it does not bypass evidence verification, safety policy, privacy policy, user provider controls, or health checks.
